## Summary — What I changed
- Fixed Bug 1 (Tooltip/aria-label mismatch)
  - Problem: `IconButton` used `aria-label="Delete current item"` while Tooltip displayed `"Delete"`.
  - Fix: Set `aria-label="Delete"` so the screen reader accessible name matches the visible tooltip and removes the mismatch.
- Fixed Bug 2 (Autocomplete caret / focus issue)
  - Problem: The Autocomplete was fully controlled, and `onInputChange` updated the `inputValue` on `reset`, causing a race/empty value on selection → caret became invisible / not at expected position when refocusing.
  - Fix:
    - In `onChange`, set both `value` and `inputValue` (keeps the input text in sync).
    - In `onInputChange`, avoid setting `inputValue` on `reset` — only set on `input` or `clear`.
    - Set `inputProps` style to `caretColor: 'black'` to ensure caret visibility across platforms.

## Important implementation notes (technical details)
- Tooltip fix:
  - I matched the `aria-label` with the visible tooltip text by updating the `IconButton` to `aria-label="Delete"`.
- Autocomplete fix:
  - The issue was caused by the `reset` reason in `onInputChange`, which sometimes sets an empty value when an option was selected.
  - I updated `onChange` to set `inputValue` explicitly to the chosen option, and restricted `onInputChange` to only handle `input` and `clear`.
  - I added `inputProps` style of `caretColor: 'black'` so that, in environments where the caret color is not obvious, it remains visible.
- Tests:
  - Puppeteer-based tests simulate user interaction (hover for tooltip, keyboard to show options, click option, blur, focus, typing).
  - The test checks:
    - Tooltip text equals `'Delete'`
    - IconButton `aria-label` equals `'Delete'`
    - After selecting a value (e.g., 'Option C'), blur and refocus keeps caret at the end and typing appends text as expected
